# ADR 011 — Internationalisation (arabe RTL / anglais)

- **Statut :** Proposed — **bibliothèque hors stack imposée : accord explicite requis**
- **Date :** 2026-11-11
- **Section de spec :** §6 (« واجهة عربية/إنجليزية »), §4.4 ; plan J8

## Contexte
La spec veut une interface arabe et anglaise. L'arabe est écrit de droite à gauche ; le plan l'introduit dès J8 (Auth).

## Fait vérifié (2026-11-05)
`next-intl` supporte l'App Router et les Server Components (`getTranslations` côté serveur, `NextIntlClientProvider` côté client), le routage par segment `[locale]` et la détermination de locale via la requête/cookie. La page consultée **ne traite pas du RTL** et **ne liste pas les versions de Next.js supportées** → **À CONFIRMER** au J4/J8. Source : https://next-intl.dev/docs/getting-started/app-router

## Décision recommandée
- Bibliothèque : **`next-intl`** (candidat), versions épinglées au J4 après vérification de compatibilité avec la version de Next.js retenue.
- Locales : `ar` (par défaut, `dir="rtl"`) et `en` (`dir="ltr"`) ; le RTL est géré par l'attribut `dir` sur `<html>` et des propriétés CSS logiques (`margin-inline-start`, `padding-inline`, etc.), sans styles dépendant de gauche/droite.
- Fichiers de messages : `apps/web/messages/{ar,en}.json` ; aucune chaîne en dur dans les composants (lint).
- Textes légaux de consentement et de désabonnement : versionnés et stockés dans la langue du contact (`contacts.language`).
- Dates, nombres, devises : `Intl` selon la locale ; chiffres : arabes occidentaux ou orientaux à décider avec le produit (à confirmer).
- Tests Playwright en AR (RTL) et EN.

## Alternatives
Autre bibliothèque i18n ou i18n maison : plus de code à maintenir ; à n'envisager que si `next-intl` s'avère incompatible.

## Conséquences
Chaque écran livré est bilingue dès sa création (pas de rattrapage final). Risque R11 : coût RTL sous-estimé → ADR visible dès J8.
