L'idée à retenir pour expliquer : l'application est multi-entreprises. Chaque entreprise est isolée des autres ; ce que chaque personne voit et fait dépend de son rôle. Ce contrôle est appliqué deux fois : dans l'application et dans la base de données.

1. Connexion, inscription, mot de passe oublié

À quoi ça sert : entrer dans l'application de façon sûre. Les messages d'erreur sont volontairement vagues (« adresse ou mot de passe incorrect ») pour ne pas révéler si un compte existe.

Quoi faireCe que vous devez voir
Ouvrir /fr, cliquer Se connecter, saisir un mauvais mot de passeNotification rouge, pas de connexion
Se connecter avec alpha-admin@seed.testArrivée sur le Tableau de bord
Se déconnecter, puis taper directement /fr/membersRetour à la connexion, puis à la page demandée après connexion
Mot de passe oublié avec une adresse inexistanteMême message de succès qu'avec une vraie adresse
Point à montrer : les e-mails (confirmation, réinitialisation) arrivent dans Mailtrap, pas chez de vrais clients.

12. Langues, sens de lecture et mode sombre

  • Changer la langue en haut (français, anglais, arabe). En arabe l'écran passe de droite à gauche : menu à droite, flèches inversées.
  • Basculer le mode sombre (icône soleil/lune) : tout reste lisible (le contraste est vérifié automatiquement).
  • Réduire la fenêtre : le menu latéral devient un tiroir.

14. Si quelque chose ne marche pas

  • Page blanche ou erreur : vérifier que pnpm dev tourne ; « Another next dev server is already running » veut dire qu'un serveur tourne déjà sur le port 3000.
  • Données abîmées : pnpm db:reset remet la base à l'état de départ.
  • Pour chaque anomalie : noter l'écran, le compte utilisé, ce que vous attendiez, ce que vous avez vu, et joindre une capture.
